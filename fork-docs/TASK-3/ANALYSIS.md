# TASK-3: Доступ на префикс топиков

## Источник

Запрос от команды аналитики: нужен доступ не на один топик, а на весь префикс команды. Аналитикам всегда нужно читать все топики команды целиком.

## Проблема

Текущая реализация (TASK-1) поддерживает только запрос доступа на конкретный топик. Аналитик, которому нужно читать все топики команды (например, `atom.*`), вынужден запрашивать доступ на каждый топик отдельно. При появлении нового топика — запрашивать снова.

## Требования

1. Пользователь может запросить доступ на префикс (например, `atom.*`) — одним запросом
2. При одобрении доступ даётся на все текущие и будущие топики с этим префиксом
3. Owner аппрувит запрос на свой префикс (логика из `prefix-owners`)
4. В Manage Accesses видно что доступ выдан на префикс, а не на отдельный топик

## Что потребуется (предварительно)

### Backend
- Новая сущность или расширение `TopicAccessEntity` — поле `prefix` вместо/помимо `topicName`
- Расширение `AccessRequestEntity` — запрос может быть на префикс
- Логика в `DatabaseClaimProvider` — при проверке прав учитывать prefix-based доступы
- Миграция БД (V2)

### Frontend
- UI для запроса доступа на префикс (выбор: конкретный топик vs префикс)
- Отображение prefix-based доступов в таблицах

### Открытые вопросы
- Какие префиксы доступны для запроса? Только из `prefix-owners` или произвольные?
- Может ли пользователь иметь одновременно доступ на топик и на префикс?
- Как отображать в UI: отдельная таблица или вместе с topic-based доступами?
