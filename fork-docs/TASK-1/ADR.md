# ADR: Система самообслуживания доступов к топикам

## Статус

Принято

## Проблема

Несколько команд работают с одной Kafka. Топики разделены по префиксам (eis.*, edo.*, pc.*). Для выдачи доступа сотруднику другой команды нужно вручную править YAML-конфигурацию AKHQ и передеплоивать. Это медленно, не масштабируется, создаёт нагрузку на инфраструктурную команду.

## Решение

Добавить в AKHQ UI для запроса и одобрения доступов к конкретным топикам. Доступы хранятся в PostgreSQL, одобряют владельцы префиксов. Фича работает поверх существующей системы ролей AKHQ, не заменяя её.

## Ключевые решения

| Решение | Обоснование |
|---------|-------------|
| PostgreSQL + Flyway | Надёжное хранение, стандартные миграции. Micronaut Data JPA из коробки |
| Обёртка над ClaimProvider, а не замена | Минимальные изменения в оригинальном коде, rebase-friendly |
| Владельцы префиксов в YAML (username + email) | Меняются редко, не нужны LDAP-запросы за членами групп |
| Доступ на уровне конкретного топика | Гранулярнее чем по префиксу, безопаснее |
| Роли READ/WRITE маппятся на существующие akhq-роли | Не изобретаем новую систему авторизации |
| `enabled: false` выключает всю фичу | Форк ведёт себя как оригинал, безопасный откат |
| Email-уведомления опциональны | Можно начать без SMTP, события пишутся в лог |

## Контекст

- Форк синхронизируется с оригиналом через rebase
- Аутентификация — доменная (LDAP)
- Один кластер Kafka
- Доступ бессрочный
- Запрос строго на один топик за раз
