# Spec Delta

## MODIFIED Requirements

### Requirement: Секция управления для владельцев и суперадминов
Секция «Manage Accesses» SHALL отображаться, только если хотя бы один из ответов `requests/pending`, `requests/all` или `accesses` для текущего пользователя непуст. Секция MUST содержать вкладки Pending, History и Accesses. Accesses SHALL показывать активные и отозванные доступы со статусом Active или Revoked; для отозванных MUST отображаться `revokedBy` и `revokedAt`. Кнопка Revoke с подтверждением SHALL быть доступна только для активных записей. После любого действия UI SHALL показывать уведомление и перезагружать данные страницы.

#### Scenario: Владелец одобряет запрос из UI
- **WHEN** владелец на вкладке Pending нажимает Approve
- **THEN** появляется уведомление `Request approved`, запрос исчезает из Pending и отображается в History со статусом Approved

#### Scenario: Отзыв с подтверждением
- **WHEN** владелец нажимает Revoke на вкладке Accesses и подтверждает действие
- **THEN** выполняется `DELETE /accesses/{id}`, после обновления запись остаётся в списке со статусом Revoked, автором и датой отзыва, а кнопка Revoke у неё отсутствует

#### Scenario: Активный и отозванный доступы в одном списке
- **WHEN** у владельца есть активный доступ и ранее отозванный доступ в его зоне ответственности
- **THEN** вкладка Accesses показывает обе записи: активную со статусом Active и кнопкой Revoke, отозванную со статусом Revoked и данными `revokedBy`/`revokedAt`

#### Scenario: Пользователь без зоны ответственности
- **WHEN** у пользователя пусты все три списка управления
- **THEN** секция Manage Accesses не отображается
