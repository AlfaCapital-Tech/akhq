# Proposal

## Why

Отзыв доступа сейчас физически удаляет запись, поэтому владелец не видит, какие права уже отозваны, кто и когда это сделал. Нужно сохранять историю отзывов, не оставляя отозванным записям никаких прав.

## What Changes

- Отзыв доступа становится soft-delete: запись сохраняется с `revokedBy` и `revokedAt`, а активный доступ определяется по `revokedAt == null`.
- Отозванные доступы не участвуют в авторизации, не отображаются как текущие у заявителя и не мешают повторной выдаче той же роли на ту же цель.
- Повторная выдача создаёт новую активную запись; предыдущие отозванные записи остаются в истории. Одновременно допустим только один активный доступ для сочетания пользователя, цели и роли.
- `GET /accesses` возвращает активные и отозванные доступы в зоне ответственности; повторный отзыв не перезаписывает автора и время первого отзыва.
- Вкладка Current Accesses переименовывается в Accesses и показывает оба состояния, автора и дату отзыва; кнопка Revoke доступна только для активной записи.
- Миграция V4 добавляет поля отзыва и ограничивает уникальность только активными записями. Ранее физически удалённые записи не восстанавливаются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `topic-access-requests`: хранение отозванных доступов, их исключение из действующих прав и повторная выдача после отзыва.
- `access-management-ui`: единый список активных и отозванных доступов с информацией об отзыве.

## Impact

- Бэкенд: `TopicAccessEntity`, `TopicAccessRepository`, `AccessManagementController`, `DatabaseClaimProvider`.
- БД: новая миграция Flyway V4 для `topic_access`; существующие записи остаются активными.
- API: поля `revokedBy`/`revokedAt` в ответах доступов; `DELETE /accesses/{id}` сохраняет запись вместо удаления.
- Фронтенд: `AccessManagement.jsx` и текст тура Access Management.
- Тесты: контроллер, динамические группы, повторная выдача и UI-сборка; новых зависимостей не требуется.
