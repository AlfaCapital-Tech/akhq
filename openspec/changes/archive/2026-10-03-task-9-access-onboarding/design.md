# Design

## Context

- После TASK-8 `Topic.jsx` — версия upstream с правкой форка (кнопка Request Access в шапке). Вкладка Data показывается по глобальному списку ролей из `sessionStorage.roles`, где паттерны топиков уже потеряны: при `TOPIC_DATA:READ` хоть на один топик вкладка видна на всех, и чужой топик даёт 403; без этой роли страница молча открывает Configs.
- `/api/me` отдаёт роли с паттернами, но клиент сворачивает их в `ресурс → действия`. Решать «может ли пользователь читать этот топик» на клиенте нельзя, нужен сервер.
- Владелец и суперадмин определяются в `AccessManagementController` (`isSuperAdmin`, `getOwnedPrefixes`), отдельного признака «согласующий» API не отдаёт; бейдж Access показывает только число ожидающих запросов.
- Пункт Access в `Sidebar.jsx` и страница `AccessManagement.jsx` — код форка. Тур можно привязать к ним без правок upstream.
- `react-joyride` 3.2.0 поддерживает React 19 (`peerDependencies: react 16.8 - 19`), есть свой `tooltipComponent`.
- Картинки маскота сгенерированы по фирменным стикерам и лежат в `assets/` этого change: `wave`, `wave-blink`, `point`, `think`, `happy`, WebP 512×512 с прозрачностью, ~25–30 КБ.

## Goals / Non-Goals

**Goals:**
- Пользователь узнаёт о самообслуживании в момент, когда ему нужен доступ, и один раз после релиза
- Минимум правок в файлах upstream: всё новое — в каталоге форка

**Non-Goals:**
- Демо-песочница с моками и проп `demoMode` в модалках
- Хранение признаков онбординга в PostgreSQL
- Переименование пункта Access
- Перевод существующего английского интерфейса форка

## Decisions

### Тур по реальному интерфейсу страницы Access Management
Тур живёт на одной странице: пункт Access в меню виден везде, остальные цели — на странице Access Management. Шаг про кнопку Request Access на топике и форму запроса — карточка по центру, без перехода на топик. Многостраничный тур с навигацией между шагами хрупкий, а песочница дублирует экраны, которые upstream переписывает (#3235).

Цели помечаются атрибутом `data-tour="…"` (пункт меню, таблица My Requests, кнопка запроса на префикс, вкладка Pending). Анонс «Показать» открывает `/ui/{cluster}/access-management?tour=1`; страница запускает тур после загрузки своих данных. На странице есть кнопка повторного запуска.

### Шаги про одобрение — по `GET /me`
Новый эндпоинт `GET /api/{cluster}/access-management/me` → `{approver}` на существующих `isSuperAdmin`/`getOwnedPrefixes`. Вызывается при старте тура. Если секция Manage Accesses скрыта (все списки пусты), шаги про одобрение идут карточкой по центру.

### Право читать топик — по `GET /topic/{topicName}/data-access`
Эндпоинт берёт итоговые группы пользователя через `UserGroupsResolver` (после TASK-8 его подменяет класс форка, так что выданные доступы учтены) и проверяет: есть группа, чья роль содержит `TOPIC_DATA` + `READ`, кластер матчит `{cluster}`, паттерн матчит имя топика. Это повторяет логику `AbstractController.checkIfClusterAndResourceAllowed`; переиспользовать её нельзя — она берёт ресурс из аннотации вызывающего метода. Ответ всегда `200 {read}`, без 403: UI не должен показывать ошибку.

### Страница топика: вкладка Data с плашкой
Правки `Topic.jsx`, только при `accessManagementEnabled`:
1. Вкладка Data показывается всегда; по умолчанию открывается она, а не Configs
2. Содержимое вкладки обёрнуто компонентом форка: он запрашивает `data-access` и при `read: false` рисует плашку с кнопкой Request Access (существующая модалка) и вызывает подсказку маскота; при `read: true` рендерит штатный `TopicData`

При выключенной функции условия в `Topic.jsx` прежние. Цель — дифф в `Topic.jsx` не больше ~10 строк.

### Маскот: один компонент и состояние в браузере
Компоненты форка — в `client/src/containers/AccessManagement/Onboarding/`: маскот (поза, облачко, кнопки), тур (`react-joyride` с `tooltipComponent` в виде маскота с облачком), плашка топика, модуль состояния. Маскот монтируется один раз в `AkhqRoutes.jsx` (файл уже изменён форком).

Состояние:
- `localStorage['akhq.onboarding.tour']` — номер пройденной версии тура
- `localStorage['akhq.onboarding.mascot'] = 'off'` — «Больше не показывать»
- `sessionStorage['akhq.onboarding.shown.<место>']` — показ в этом месте в текущей сессии

Доступ к хранилищам — в `try/catch`: в приватном режиме они могут бросать исключение, тогда маскот просто не появляется сам. Версия тура — константа в коде фронтенда: содержимое тура меняется только вместе с кодом, отдельная настройка не нужна.

Анонс делает сам маскот, отдельного баннера нет: один элемент вместо двух. Если понадобится баннер для тех, кто отключил маскота, его легко добавить.

### Анимация и доступность
CSS: выезд снизу, лёгкое покачивание, моргание сменой кадров `wave`/`wave-blink` раз в несколько секунд. При `prefers-reduced-motion: reduce` анимаций нет. У картинки `alt`, кнопки облачка доступны с клавиатуры. Маскот прячется, пока открыто модальное окно.

## Risks / Trade-offs

- `Topic.jsx` — файл upstream, правка добавит конфликтов при будущих вливаниях → держать дифф минимальным, логику — в компоненте форка
- Проверка `data-access` дублирует правило прав upstream и может разойтись с ним при изменениях upstream → тесты на статические группы, выданный доступ на топик и на префикс, чужой кластер
- Цели тура рендерятся после загрузки данных → запускать тур после загрузки, шаг без цели показывать по центру
- Слои `react-joyride` и модалок Bootstrap могут перекрываться → проверить вручную открытие модалки поверх тура
- Признаки в `localStorage` привязаны к браузеру: на новом компьютере анонс покажется снова — для анонса это приемлемо
- Новая зависимость `react-joyride` — загрузка из npm может упереться в сеть
- Картинки Гаврюши попадают в публичный репозиторий — владелец бренда это разрешил
