# Proposal

## Why

После отправки запроса на доступ заявитель не видит, кто его рассматривает. Владельцы показываются только в момент создания запроса, в модалке; в таблице My Requests и в карточке запроса по ссылке их нет. Если запрос висит, заявитель не знает, кому написать. Замечание инфраструктуры при приёмке TASK-10 (диплинк и напоминания).

## What Changes

- В ответе `GET /requests/my` (и в ответе на создание запроса) у каждого запроса появляется поле `approvers`: владельцы префикса цели, а если владельцев нет — суперадмины. Правило совпадает с адресатами писем
- Таблица My Requests получает колонку Approvers: имена согласующих со ссылками `mailto:`
- Карточка запроса, открытого заявителем по ссылке из письма, вместо «Waiting for the owner's decision» показывает, чьего решения ждёт запрос

## Capabilities

### Modified Capabilities

- `topic-access-requests`: поле `approvers` в собственных запросах пользователя
- `access-management-ui`: согласующие в My Requests и в карточке запроса заявителя

## Impact

- Бэкенд: `AccessRequestEntity` (вычисляемое `@Transient` поле), новый DTO `Approver`, `AccessManagementController` (заполнение поля в `/requests/my` и при создании); БД и миграции не меняются
- Фронтенд: `AccessManagement.jsx` (колонка, рендер списка), `RequestCard.jsx`, хелпер `approversOf` в `linkedRequest.js`; файлы upstream не трогаем
