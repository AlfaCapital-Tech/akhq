## ADDED Requirements

### Requirement: Сведения о правах текущего пользователя
Сервер SHALL предоставлять любому аутентифицированному пользователю: `GET /me` — `{approver}`, где `approver = true`, если пользователь суперадмин или владелец хотя бы одного префикса из `prefix-owners`; `GET /topic/{topicName}/data-access` — `{read}`, где `read = true`, если пользователь может читать сообщения этого топика в этом кластере по итоговому набору групп (статические группы и выданные доступы, как при проверке прав на чтение данных). Оба эндпоинта MUST NOT изменять данные и при выключенной функции SHALL отвечать `404`, как остальные эндпоинты access management.

#### Scenario: Владелец префикса
- **WHEN** пользователь `owner-a`, указанный владельцем `team-a\..*`, вызывает `GET /me`
- **THEN** ответ `{approver: true}`

#### Scenario: Обычный пользователь
- **WHEN** пользователь, не являющийся ни владельцем, ни суперадмином, вызывает `GET /me`
- **THEN** ответ `{approver: false}`

#### Scenario: Доступ на префикс даёт чтение
- **WHEN** у `alice` выданный доступ `READ` на префикс `team-a\..*` и она вызывает `GET /topic/team-a.orders/data-access`
- **THEN** ответ `{read: true}`

#### Scenario: Нет прав на топик
- **WHEN** у `alice` нет ни статических, ни выданных прав на чтение `team-b.events`
- **THEN** `GET /topic/team-b.events/data-access` отвечает `{read: false}` с кодом `200`, а не `403`
