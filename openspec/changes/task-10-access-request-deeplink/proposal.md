# Proposal

## Why

Письмо о новом запросе на доступ ведёт на `<base-url>/ui`. Лид сам ищет кластер, раздел Access, вкладку Pending и нужную строку. Пока он не дошёл, запрос лежит; второго письма нет, бейдж в меню видят только те, кто и так заходит в AKHQ. Заявитель ждёт днями. Близкая просьба уже была раньше: различать контур и попадать на страницу запроса.

## What Changes

- Ссылка в письме ведёт на страницу Access Management того кластера, где создан запрос, с параметром запроса: `<base-url>/ui/<cluster>/access-management?request=<id>`
- Страница по этому параметру открывает вкладку Pending и показывает карточку запроса с кнопками Approve/Reject; для уже решённого запроса — его статус, кто и когда решил; для чужого или несуществующего — понятное сообщение вместо ошибки
- Вход через SSO возвращает на ту же ссылку (механизм `returnTo` уже есть, проверяется и чинится при необходимости)
- У запроса появляется кластер создания (новая колонка); старые записи без кластера ведут на первый кластер из конфига
- Напоминания владельцам о запросах в статусе Pending с интервалом `akhq.access-management.notifications.reminder-interval` (по умолчанию `3d`, `0` выключает); тема письма помечена как напоминание; после Approve/Reject напоминания прекращаются
- Напоминания работают при нескольких репликах без дублей: отметка последней отправки хранится в БД и захватывается одним UPDATE

## Capabilities

### Modified Capabilities

- `access-notifications`: ссылка на запрос вместо `/ui`, повторные напоминания, новые ключи конфига
- `topic-access-requests`: хранение кластера создания и времени последнего напоминания (миграция V3)
- `access-management-ui`: открытие страницы по ссылке на запрос — вкладка Pending, карточка запроса, статус решённого запроса

## Impact

- Бэкенд: `NotificationService` (ссылка, письмо-напоминание), новый планировщик напоминаний (код форка), `AccessRequestEntity` + репозиторий (две колонки, один запрос выборки и один условный UPDATE), `AccessManagementController` (кластер при создании), миграция `V3__access_request_cluster_reminder.sql`, свойства `NotificationProperties`
- Фронтенд: `AccessManagement.jsx` (чтение `?request=`, карточка, выбор вкладки); файлы upstream не трогаем
- Конфигурация: новый ключ `reminder-interval`; `base-url` по-прежнему обязателен для ссылки
- Деплой: миграция Flyway применяется при старте; напоминания о давно висящих запросах уйдут сразу после первого выката с включённым интервалом
